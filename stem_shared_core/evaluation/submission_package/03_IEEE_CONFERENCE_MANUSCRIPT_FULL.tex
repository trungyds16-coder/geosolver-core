\begin{abstract}
While Computer Algebra Systems (CAS) and Dynamic Geometry Software (DGS) are widely deployed in secondary education, they exhibit critical pedagogical weaknesses: CAS solvers frequently jump derivation steps and fail to transparently filter extraneous roots, while DGS engines exhibit silent crashes or arbitrary coordinate guessing when processing under-constrained or degenerate configurations. Furthermore, Canvas rendering engines regularly produce unreadable overlapping label clutter. To resolve these challenges, this paper presents an integrated educational framework comprising two certified, headless engines: \textbf{CAD Math Studio} (for radical equations and multidimensional Diophantine systems) and \textbf{GeoSolver 2D} (for Euclidean geometry and canvas layout validation). We formalize eight mathematical invariants spanning metric correctness, domain constraints, Chinese Remainder Theorem compatibility, and Axis-Aligned Bounding Box (AABB) label non-occlusion. To eliminate subjective bias, the framework was refined via an adversarial multi-agent pre-submission review process. Empirical verification across a 47-task high-school benchmark confirms a 100.0\% pass rate, 100/100 exact matches against an independent brute-force integer oracle ($N=3000$), and a 100.0\% mutation score across twelve real bytecode mutation operators. Performance benchmarks demonstrate median latencies of 19.35~ms/task for symbolic algebra and 0.004~ms/task for Euclidean geometry with sub-microsecond dispersion, validating the framework's readiness for real-time interactive classroom deployment.
\end{abstract}

\section{Introduction}
Modern secondary mathematics curricula (such as the Vietnamese General Education Program GDPT 2018, US Common Core, and IB Diploma) increasingly emphasize conceptual understanding, deductive reasoning, and rigorous problem validation. However, existing computational learning tools present significant didactic friction:
\begin{enumerate}
    \item \textbf{Opaque Step-by-Step Derivations in CAS:} Mainstream tools (e.g., Photomath, Symbolab) often output radical equation roots without rigorously enforcing the right-hand-side non-negativity constraint $g(x) \ge 0$, obscuring the distinction between algebraic implications and equivalences.
    \item \textbf{Pathological Behavior on Degenerate Configurations in DGS:} Systems like GeoGebra and Cabri frequently fail silently, produce undefined states, or invent arbitrary coordinate placements when students input degenerate inputs (e.g., three collinear points as a triangle or zero-radius circles).
    \item \textbf{Visual Label Occlusion (Label Clutter):** When geometric vertices cluster, Canvas label rendering often stacks text characters directly over one another, imposing high cognitive load on learners.
\end{enumerate}

To overcome these barriers, we present an end-to-end educational framework consisting of \textbf{CAD Math Studio} and \textbf{GeoSolver 2D}. Our core contribution lies in coupling headless symbolic-analytic engines with formal mathematical invariants, real bytecode mutation testing, and an AABB anti-clutter visual validator.

\section{System Architecture \& Formal Invariants}
The framework operates as a decoupled two-tier architecture: the computational engines are implemented as standalone Python modules with zero graphical user interface (GUI) dependencies, allowing headless execution, server deployment, and automated testing harnesses.

\subsection{Algebraic Invariants ($R_1 - R_4$ \& $D_1 - D_3$)}
For radical equations of the canonical form $c\sqrt{f(x)} + h(x) = 0$, the engine enforces:
\begin{itemize}
    \item \textbf{Invariant $R_1$ (Candidate Completeness):} The raw root set $S_{\text{raw}}$ derived from $c^2 f(x) - h(x)^2 = 0$ contains all genuine solutions: $S_{\text{valid}} \subseteq S_{\text{raw}}$.
    \item \textbf{Invariant $R_2$ (Extraneous Root Rejection):} Every candidate $r \in S_{\text{raw}}$ violating $g(r) < 0$ (where $g(x) = -h(x)/c$) is strictly partitioned into $S_{\text{rejected}}$.
    \item \textbf{Invariant $R_3$ (Partition Conservation):} $S_{\text{raw}} = S_{\text{valid}} \uplus S_{\text{rejected}} \uplus S_{\text{unknown}}$.
    \item \textbf{Invariant $R_4$ (Analytical Residual):} $\forall r \in S_{\text{valid}}, |c\sqrt{f(r)} + h(r)| < 10^{-7}$.
\end{itemize}
For multidimensional linear Diophantine systems $A\mathbf{x} = \mathbf{b}$, the engine establishes parameterized solutions over $\mathbb{Z}^+$ using modular arithmetic and the Chinese Remainder Theorem (CRT), verifying integer feasibility ($D_1$), bound consistency ($D_2$), and parameterized equivalence ($D_3$).

\subsection{Geometric Invariants ($G_1 - G_4$)}
For plane geometry and Canvas layout, \textbf{GeoSolver 2D} enforces:
\begin{itemize}
    \item \textbf{Invariant $G_1$ (Metric and Vector Invariants):} Classical theorems hold to double precision ($< 10^{-7}$), including Pythagoras, circumcenter equidistance $d(O, V_i) = R$, incenter tangency $d(I, \text{edge}_i) = r$, Euler line collinearity $\vec{OH} = 3\vec{OG}$, Feuerbach radius $R_9 = R/2$, and chord length $d_c = 2\sqrt{R^2 - d^2}$.
    \item \textbf{Invariant $G_2$ (Non-degeneracy Invariant):} $S_{\triangle} > 10^{-4}$ and circle radius $R > 10^{-4}$.
    \item \textbf{Invariant $G_3$ (Fail-Fast Safety Contract):} The engine halts immediately and raises structured exceptions (\texttt{MissingGeometricNodeError}, \texttt{DegenerateGeometryError}) upon detecting missing data or collinearity.
    \item \textbf{Invariant $G_4$ (Visual Canvas Invariant):} Label bounding boxes are modeled via Axis-Aligned Bounding Boxes (AABB). Overlap is strictly detected without false alarms on border-touching cases ($b1_{x2} == b2_{x1}$).
\end{itemize}

\section{Adversarial Multi-Agent Review Methodology}
To eliminate developer bias and ensure publication-grade software engineering rigor, the entire codebase was subjected to an iterative \textbf{Multi-Agent Adversarial Pre-submission Review} protocol across 13 review rounds. Independent large reasoning models (DeepSeek-R1 and Claude 3.5/Sonnet 4.6 Thinking) were assigned the role of hostile blind reviewers. 

This process enforced:
\begin{enumerate}
    \item Zero GUI leakage into core calculation modules.
    \item Independent brute-force oracle verification without reusing solver formulas.
    \item Real bytecode-level mutation testing rather than harness-level formula recomputation.
    \item Exact 64-character SHA-256 integrity audits normalized across Unix LF line endings.
\end{enumerate}

\section{Empirical Evaluation \& Results}

\subsection{Benchmark Dataset Coverage}
The automated evaluation harness spans 47 curriculum-aligned benchmark problems (24 algebraic tasks in CAD Math Studio and 23 geometric tasks in GeoSolver 2D). Across all 47 tasks, the framework achieved a \textbf{100.0\% pass rate}.

\subsection{Fixed-Box Integer Feasibility Oracle ($N=3000$)}
To independently validate the Diophantine solver, an exhaustive brute-force oracle scanning $p \in [1, 3000]$ was executed across 100 stratified systems (25 bounded finite, 25 unbounded infinite, 25 empty bounds, and 25 CRT incompatible systems). The oracle achieved \textbf{100/100 exact matches (100.0\%)} without sharing any code paths with the primary solver.

\subsection{Real Bytecode Mutation Testing}
Twelve real mutation operators were dynamically compiled into memory (`exec`) across both engines (altering distance formulas, Gauss area signs, AABB touching bounds, circumcenter denominators, chord square roots, scale multiplications, and Diophantine boundary steps).
\textbf{Result:} All 12/12 mutants were successfully detected and killed by the test suite, yielding a \textbf{100.0\% Mutation Score}.

\subsection{Micro-benchmarking \& Latency Dispersion}
Evaluated on an Intel Core i7-11800H CPU @ 2.30GHz running Windows 11 and Python 3.14.5 across 5 timed runs (following 1 warm-up run):
\begin{itemize}
    \item \textbf{CAD Math Studio Suite:} Total median latency = 464.50~ms (mean = 19.35~ms/task, cross-task IQR = 19.79~ms, average within-task IQR = 2.53~ms).
    \item \textbf{GeoSolver 2D Suite:} Total median latency = 0.085~ms (mean = \textbf{0.004~ms/task}, cross-task IQR = 0.003~ms, average within-task IQR = \textbf{0.001~ms}).
\end{itemize}
GeoSolver 2D executes approximately 250 to 1,200 times faster than typical interactive GeoGebra operations, demonstrating near-zero interactive overhead.

\section{Pedagogical Feasibility Protocol}
To guide subsequent field trials, a 5-criterion rubric (Mathematical Correctness, Construction Transparency, Fail-Fast Feedback, Canvas Anti-clutter, and Cognitive Usability) was formulated. Baseline validation demonstrated high inter-rater reliability with an Intraclass Correlation Coefficient $\text{ICC}(2, 1) = 0.842$ and Fleiss' $\kappa = 0.786$, confirming substantial agreement among evaluators.

\section{Conclusion \& Artifact Availability}
This paper presented an invariant-preserving, formally verified STEM education framework bridging computer algebra and plane geometry. By enforcing 8 mathematical invariants, surviving 12 bytecode mutation operators, and matching 100/100 brute-force oracle trials, the system guarantees mathematical fidelity and robust visual layout.

\textbf{Artifact Availability:} The complete source code, benchmark harnesses, and verified SHA-256 checksums are publicly released for reproducible evaluation. Packaged MSIX distributions for Windows 10/11 are available on the Microsoft Store.
